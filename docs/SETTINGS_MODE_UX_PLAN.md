# SETTINGS_MODE_UX_PLAN.md — 설정모드 조작감·가독성 정비

> 착수: 2026-08-26 · 선행: [SETTINGS_MODE_UI_PLAN.md](SETTINGS_MODE_UI_PLAN.md) S-0~S-6 완료
> **이 계획은 기능을 바꾸지 않는다.** 같은 일을 더 쉽게·더 읽기 쉽게 하는 것만 다룬다.

---

## 0. 왜 지금인가

S-0~S-6은 **화면을 만드는 일**이었다. 화면 여덟 개를 각각 다시 그렸고, 그 결과 화면끼리 조작 방식이 갈라졌다. 한 화면 안에서는 말이 되는데 화면을 옮기면 손이 다시 배워야 한다.

측정으로 확인한 갈라짐이 넷이다.

| 축 | 실측 |
|---|---|
| 버튼 높이 | **14 ~ 33px** — 화면마다 다르다 |
| 삭제 조작 | **세 가지** — raw `✕` 6패널 · `SetIconButton`+✕ 1 · 휴지통 1 |
| 되돌리기 | **1개 패널에만** 있다. 나머지 6개는 확인도 없이 즉시 삭제 |
| 추가 위치 | 목록 **위** 2 : **아래** 4 |

그리고 글자 크기가 여섯 종인데 스케일은 다섯 단계다 — `13.33px`이 밖에 있다(스와치 100개 · 이미지 셀 11개).

---

## 1. 원칙

**하나. 같은 뜻은 같은 모양으로.** 삭제는 어디서나 같은 컨트롤·같은 자리·같은 되돌리기.

**둘. 파괴적 조작에는 되돌릴 길을 준다.** 확인 대화상자보다 **삭제 후 되돌리기 토스트**를 쓴다 — 흐름을 끊지 않으면서 실수를 되돌린다(Gmail · Linear · Notion의 방식). `SetToast` + `pendingDeletes` 구현이 이미 `SettingsLibraryPanel`에 있다.

**셋. 문서 정체성은 좌측 상단에.** 지금 무엇을 편집 중인지가 항상 보이고, 그 이름이 곧 전환 지점이다(Figma · Notion · Google Docs · VS Code 공통).

**넷. 목록에서는 행 전체가 대상이다.** 이름을 읽고 오른쪽 끝의 작은 버튼으로 이동하게 만들지 않는다(Finder · 탐색기 · Figma 최근 파일).

## 2. U-1 — 시나리오 전환 ✅ 완료 (2026-08-26)

### 지금 상태 (1280px 실측)

```
사이드바 240 │ 본문 1040 ──────────────────────────┤
                    저장·목록 툴바 x562 (우측 정렬)
                              저장목록 팝업 x740 w520
                                        └ 오른쪽 여백 20px
```

세 가지가 겹친다.

1. **정체성이 오른쪽에 있다.** 시선은 왼쪽 위에서 시작하는데 "무엇을 편집 중인가"가 반대편이다
2. **팝업이 메뉴도 대화상자도 아니다.** 520×260 패널이 오른쪽 끝에 붙고, 여는 버튼(x766)과 팝업(x740)의 모서리도 안 맞는다
3. **행마다 두 번 조준한다.** `불러오기`(77×26)와 삭제(26×26)가 오른쪽 끝에 나란히 있다

### 가는 곳

```
┌──────────────────────────────────────────────┐
│ ▾ 강릉 3층 상가 화재        ● 저장 안 됨      │  이름이 곧 전환 버튼
├──────────────────────────────────────────────┤
│  🔍 시나리오 검색…                            │
│  ────────────────────────────────────────    │
│  ● 강릉 3층 상가 화재        2일 전           │  행 전체 = 불러오기
│    속초 지하주차장           1주 전      ⋯    │  삭제는 ⋯ 안으로
│    양양 물류창고             3주 전      ⋯    │
│  ────────────────────────────────────────    │
│  + 새 시나리오   다른 이름으로   ⬆   ⬇       │
└──────────────────────────────────────────────┘
```

- `저장 목록` 버튼이 사라진다 — 이름 자체가 트리거다
- 목록은 이름 **바로 아래**로 열린다(좌측 정렬). 앵커가 분명해진다
- **인라인 이름 편집은 유지한다.** 시나리오를 쓰면서 이름을 자주 고치므로, 이름은 입력칸으로 두고 그 옆에 붙은 `▾`가 목록을 연다. 둘이 시각적으로 한 컨트롤이다
- `다른 이름으로`는 목록 바닥 액션으로 내린다(Figma·Google Docs가 파일 메뉴에 두는 자리). 툴바에는 `저장`만 남는다
- 항목이 많아지면 검색이 필요하다 — 8건 이상일 때만 검색칸을 그린다

### 완료 기준

- 이름·목록·상태칩이 **본문 좌측 정렬** (x = 사이드바 우측 경계)
- 목록 왼쪽 모서리가 이름 입력칸의 왼쪽 모서리와 **일치**
- 행 어디를 눌러도 불러오기. 삭제는 행 메뉴 안
- 현재 시나리오 행에 표시가 있고 다시 불러올 수 없다
- Esc·바깥 클릭으로 닫힌다. 열려 있을 때 `aria-expanded`

## 3. U-2 — 삭제 통일과 되돌리기

`SettingsLibraryPanel`의 `pendingDeletes` + `SetToast` 패턴을 **공용 훅**으로 올린다.

| 대상 | 지금 | 뒤 |
|---|---|---|
| 체크리스트 섹션·항목 | raw `✕`, 즉시 삭제 | `SetIconButton`, 되돌리기 5초 |
| 지휘절차 카테고리·항목 | raw `✕`, 즉시 삭제 | 〃 |
| 임무·상태 프리셋 | raw `✕`, 즉시 삭제 | 〃 |
| 상태 메시지 | raw `✕`, 즉시 삭제 | 〃 |
| 구조대상자 | raw `✕`, 즉시 삭제 | 〃 |
| 건물(소방시설 행) | raw `✕`, 즉시 삭제 | 〃 |
| 출동대 유관기관·직접입력 | `SetIconButton`+✕ | 되돌리기 추가 |

체크리스트 섹션 삭제는 **항목이 통째로 날아간다.** 여기가 가장 급하다.

## 4. U-3 — 컨트롤 크기 3단

| 단 | 높이 | 쓰는 곳 |
|---|---|---|
| `sm` | 26px | 행 안 보조 버튼 |
| `md` | 32px | 기본 — 입력·셀렉트·주요 버튼 |
| `lg` | 40px | 화면당 하나 있을까 말까 한 주 동작 |

- 색 스와치 **14×14 → 24×24** (WCAG 2.5.8). 100개가 전부 위반이다
- `13.33px` 글자를 스케일 안으로 (12 / 14 / 16 / 18 / 24)

## 5. U-4 — 추가 컨트롤 위치

목록 **아래**로 통일한다(4:2에서 다수 쪽). 목록이 스크롤 영역이면 추가 행을 `position: sticky; bottom: 0`으로 붙여 스크롤해도 닿게 한다.

## 6. U-5 — 행 채움률 (후순위)

2560px 중앙값 실측.

| 화면 | 채움률 |
|---|---|
| 현장요소 · 구조대상자 · 지휘절차 | 93~95% |
| 출동대 | 48.7% |
| 건물 · 소방시설 | **35.6%** |

넓은 화면 전용 문제라 순위가 낮다. 감사 스크립트의 목표 60%는 **잠정값**이다 — 여러 화면을 재서 합의된 기준을 먼저 정해야 한다.

동작 확인 — 행 클릭 전환 ✓ · 전환 후 자동 닫힘 ✓ · 현재 항목 표시·잠금 ✓ ·
Esc 닫힘 ✓ · 바깥 클릭 닫힘 ✓ · 삭제가 행 메뉴 안 ✓ · 「다른 이름으로 저장」이
목록 바닥 ✓

### 걸린 것

목록을 `.slp__switcher` 에 걸었더니 라벨 폭(88px)만큼 왼쪽으로 밀려 모서리가
어긋났다. 기준점은 **이름 상자**여야 하는데, 그 상자는 `overflow: hidden`
(모서리를 한 번만 자르려고)이라 기준점이 될 수 없다 — `.slp__switcher-anchor`
를 한 겹 두어 해결했다.

`border-radius: 0 var(--set-r-sm) …` 의 리터럴 `0` 이 토큰 규칙에 걸렸다.
단축값을 쓰지 않고 부모의 `overflow: hidden` 으로 자르게 바꿨다 — 안쪽 요소가
각자 반경을 갖지 않아 더 낫다.

### U-1 후속 — 발견성 (2026-08-26)

「백업에서 복원했더니 시나리오가 목록에 안 보인다」는 보고를 받았다.

**데이터는 멀쩡했다.** 실제 백업 파일(시나리오 11건)로 복원해 보니
localStorage 에도 화면에도 11건이 전부 들어온다. 문제는 다른 데 있었다 —
U-1 이 「저장 목록」 버튼을 없앴는데, 복원 직후 목록을 찾을 곳이 라벨 없는
`▾` 하나뿐이었다. **내가 만든 발견성 회귀다.**

고친 것:

- 토글에 **시나리오 개수**를 함께 보인다(`11 ▾`). 숫자가 「뒤에 목록이 있다」는
  신호다. 1건 이하면 그리지 않는다
- 복원 직후 **목록을 저절로 연다.** 복원은 새로고침으로 끝나므로
  (여러 store 가 마운트 때만 localStorage 를 읽는다) 일회용 세션 플래그로
  건너뛴다. `importSettings` 가 복원 건수를 돌려주게 바꿔 토스트에 적는다
- 플래그는 **읽기만** 초기값에서 하고 지우는 것은 effect 에서 한다 —
  초기화 함수에서 지우면 StrictMode 의 두 번째 호출이 null 을 본다

교훈: **라벨을 지우면 그 자리에 다른 신호를 놔야 한다.** 「저장 목록」이라는
글자를 없앤 대가를 개수 표시로 치렀다.
