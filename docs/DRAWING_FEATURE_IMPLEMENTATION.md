# 전술상황판 전체 그림판 기능 구현 보고서

## 1. 구현 범위

훈련창의 A·B·C·D면과 건물 부분 전체를 하나의 연속된 캔버스로 인식하는 자유선 그리기 기능을 추가했다.

- A면 좌측 상단에 그리기 도구상자 배치
- A·B·C·D면과 건물 영역을 끊김 없이 연결하여 그리기
- 빨강, 파랑, 노랑 선 색상 선택
- `그리기` 버튼으로 그리기 모드 진입
- 마우스 왼쪽 버튼을 누른 상태로 이동하여 자유선 작성
- 마우스 버튼을 놓으면 현재 획 확정
- 우클릭 또는 `ESC`로 그리기 모드 취소
- `지우기` 모드에서 선을 클릭하거나 드래그하여 획 단위 삭제
- 최근 선 추가·삭제·전체 삭제 작업 실행 취소
- 확인 절차를 거친 전체 선 삭제
- 그리기·지우기 모드에서 전술상황판 전체의 기존 토큰 조작과 높이 조절 차단
- 훈련 세팅 시 그림과 진행 중인 작업 모드 초기화

우클릭으로 취소할 때는 작성 중인 미완성 획만 폐기하고 현재 그리기 또는 지우기 모드를 종료한다. 이미 완성된 선은 유지된다.

## 2. 사용자 조작

1. A면 좌측 상단에서 빨강, 파랑, 노랑 중 하나를 선택한다.
2. `그리기` 버튼을 누른다.
3. A·B·C·D면 또는 건물 영역에서 왼쪽 버튼을 누른 채 마우스를 이동한다.
4. 왼쪽 버튼을 놓아 선을 확정한다.
5. 계속해서 다른 선을 그리거나 색상을 변경한다.
6. `지우기`를 누른 뒤 삭제할 선을 클릭하거나 누른 채 지나가면 해당 획 전체가 삭제된다.
7. `↶` 버튼 또는 그리기·지우기 모드 중 `Ctrl+Z`/`Cmd+Z`로 최근 그림 작업을 되돌린다.
8. `전체 삭제`를 누르고 확인하면 완성된 선을 모두 삭제한다.
9. 우클릭, `ESC`, 하단 안내 배너 또는 모드 종료 버튼으로 현재 모드를 종료한다.

단순 클릭처럼 이동 지점이 하나뿐인 입력은 선으로 저장하지 않는다.

## 3. 구현 구조

### 상태 관리

`src/context/DrawingContext.tsx`에서 다음 상태를 관리한다.

- 현재 선택 색상
- 완성된 선 목록
- 현재 작성 중인 선
- 최대 50단계의 완성 선 상태 이력
- 선 시작, 지점 추가, 확정 및 미완성 선 취소
- 획 삭제, 전체 삭제 및 최근 작업 실행 취소

그림의 한 점은 `TacticalArea` 전체를 기준으로 `0~1` 사이의 상대좌표로 저장한다. A·B·C·D면과 건물이 동일한 좌표계를 사용하므로 한 면에서 건물을 지나 다른 면까지 하나의 획으로 이어 그릴 수 있다. 창 크기 또는 체크리스트 패널 폭이 변경되어도 전술상황판 안에서 같은 상대 위치를 유지한다.

### 작업 모드

`ActionModeContext`에 `drawing`과 `drawing-erase` 타입을 추가했다. 기존 방수 위치 선택, 송수 연결, 구조대상자 선택 등의 모드와 그리기·지우기 모드가 동시에 활성화되지 않는다.

`ActionModeProvider`는 `runKey`로 재마운트되므로 `훈련 세팅` 실행 시 남아 있던 그리기 모드도 종료된다.

### 화면 렌더링

`src/components/drawing/DrawingBoard.tsx`는 다음 세 부분으로 구성된다.

- SVG 선 표시 레이어: 입력을 받지 않고 완성 선과 현재 선만 표시
- 포인터 입력 레이어: 그리기 또는 지우기 모드일 때 전술상황판 전체에서 입력 수신
- 도구상자: 그리기·지우기 모드 전환, 색상 선택, 실행 취소 및 전체 삭제

입력에는 마우스 이벤트 대신 Pointer Events를 사용했다. 포인터 캡처를 적용하여 선 작성 중 포인터가 전술상황판 밖으로 잠시 이동해도 버튼을 놓는 이벤트를 받을 수 있도록 했다.

연속 이동 이벤트가 지나치게 많이 저장되지 않도록 직전 입력 위치에서 3px 이상 이동했을 때만 다음 점을 추가한다.

지우기 모드는 포인터와 각 선분 사이의 화면상 거리를 계산한다. 선 중심에서 14px 안에 들어오는 가장 가까운 획 하나를 삭제하므로 가는 선도 비교적 쉽게 선택할 수 있다. 마우스를 누른 채 이동하면 경로에 닿는 획을 연속으로 삭제한다. 선의 일부만 자르는 픽셀 지우개 방식이 아니라 한 번 그린 획 전체를 삭제하는 방식이다.

실행 취소 이력은 새 선 확정, 획 삭제, 전체 삭제 직전의 선 목록을 저장한다. 작성 중인 미완성 선이 있으면 실행 취소 시 해당 선을 먼저 폐기한다. 전체 삭제는 브라우저 확인창에서 동의한 경우에만 실행된다.

## 4. 기존 기능과의 충돌 방지

| 대상 기능 | 일반 상태 | 그리기·지우기 상태의 처리 |
|---|---|---|
| 출동대 토큰 드래그·메뉴 | 정상 사용 | 그리기·지우기 입력 레이어가 차단 |
| 구조대상자 드래그·메뉴 | 정상 사용 | 그리기·지우기 입력 레이어가 차단 |
| 이벤트 토큰 조작 | 정상 사용 | 이벤트 토큰의 포인터 입력 비활성화 |
| 소화전·연결송수구 조작 | 정상 사용 | 그리기·지우기 입력 레이어가 차단 |
| 건물/A면 높이 조절 | 정상 사용 | 그리기·지우기 중 리사이즈 핸들 비활성화 |
| 방수·송수·고가차 대상 선택 | 정상 사용 | ActionMode 단일화로 동시 실행 방지 |
| 우클릭 메뉴 | 기존 동작 | 미완성 선 폐기 후 현재 모드 종료 |
| ESC | 기존 작업 모드 취소 | 미완성 선 폐기 후 현재 모드 종료 |

완성된 그림 SVG는 `pointer-events: none`이므로 그리기 모드 종료 후 기존 조작을 가로채지 않는다.

## 5. 데이터 수명과 현재 제한

- 그림은 현재 PlayPage가 유지되는 동안 메모리에 보관된다.
- 훈련을 종료해도 같은 화면에서는 그림이 유지된다.
- `훈련 세팅`을 누르면 그림이 모두 초기화된다.
- 브라우저 새로고침 또는 PlayPage 재마운트 시 그림은 복원되지 않는다.
- 지우기는 선의 일부가 아닌 한 획 전체를 삭제한다.
- 실행 취소 이력은 최근 50단계까지만 유지되며 다시 실행 기능은 제공하지 않는다.
- 그림은 이벤트 로그 또는 분석 결과에 기록되지 않는다.
- 현재 선 굵기는 화면에서 약 4px로 고정된다.

### 확인하지 못한 검증

실행 환경에서 연결 가능한 브라우저가 제공되지 않아 자동화된 실제 마우스 드로잉과 화면 캡처 검증은 수행하지 못했다. 배포 또는 병합 전 아래 수동 검증을 권장한다.

1. 세 색상으로 각각 선이 표시되는지 확인
2. 토큰 위에서 그려도 토큰이 이동하지 않는지 확인
3. 이벤트 토큰 위에서 그리기가 이어지는지 확인
4. 작성 중 우클릭 시 미완성 획만 사라지는지 확인
5. 완성된 선이 있는 상태에서 우클릭 시 완성 선은 유지되는지 확인
6. ESC와 `그리기 종료` 버튼으로 정상 종료되는지 확인
7. 그리기 종료 후 토큰 드래그와 우클릭 메뉴가 복원되는지 확인
8. A면 높이와 좌측 패널 폭 변경 후 선이 전체 캔버스 상대좌표에 맞춰 함께 조정되는지 확인
9. `훈련 세팅` 후 그림과 그리기 모드가 초기화되는지 확인
10. 지우기 클릭과 드래그로 닿은 획만 삭제되는지 확인
11. 선 추가, 획 삭제 및 전체 삭제 후 실행 취소가 이전 상태를 복원하는지 확인
12. 전체 삭제 취소 시 선이 유지되고 확인 시 모든 선이 삭제되는지 확인

## 7. 오류 발생 가능 부분

### 높은 빈도의 포인터 입력

3px 간격으로 점을 제한했지만 매우 긴 시간 동안 많은 선을 그리면 상태 배열과 SVG 점 수가 증가해 렌더링이 느려질 수 있다. 실제 장시간 훈련에서 문제가 발생하면 획 단순화 알고리즘 또는 최대 획 수 제한이 필요하다.

### 인접하거나 겹친 획 삭제

지우개 반경 안에 여러 획이 있으면 포인터에서 가장 가까운 획을 우선 삭제한다. 선이 정확히 겹친 경우 가장 나중에 그린 획부터 선택될 수 있으며, 누른 채 움직이면 아래쪽 획도 연속해서 삭제될 수 있다. 세밀한 부분 삭제가 필요하면 향후 획 분할 방식의 픽셀 지우개가 별도로 필요하다.

### 실행 취소 이력 메모리

실행 취소를 위해 선 목록의 이전 상태를 최대 50단계 보관한다. 일반적인 훈련 사용에는 충분하지만 매우 많은 좌표를 가진 선을 반복해서 추가·삭제하면 메모리 사용량이 늘어날 수 있다. 현재는 단계 수 제한으로 증가 범위를 제한한다.

### 전술상황판 크기 변경에 따른 그림 변형

상대좌표 저장 방식이므로 전술상황판 전체의 가로·세로 비율이 바뀌면 그림도 해당 비율로 늘어나거나 줄어든다. 위치 유지에는 적합하지만 원본의 절대 비율을 보존하지는 않는다. 건물/A면 높이만 변경하는 경우에도 전체 좌표계에서 각 내부 영역의 경계가 이동하므로 기존 선과 해당 영역의 상대적인 정렬이 달라질 수 있다.

### 브라우저 밖에서 포인터가 해제되는 경우

Pointer Capture와 `pointercancel`을 처리했지만 운영체제 수준에서 브라우저 포커스가 강제로 사라지는 특수 상황에서는 마지막 획이 취소될 수 있다. 미완성 획이 잘못 확정되는 것보다 폐기하는 방향으로 처리했다.

### 터치 장치의 취소 조작

선 입력 자체는 Pointer Events로 동작하지만 터치 장치에는 우클릭과 물리 ESC가 없을 수 있다. 이 경우 화면의 `그리기 종료` 버튼을 사용해야 한다. 두 손가락 제스처나 길게 누르기를 우클릭 취소로 별도 구현하지 않았다.

### 외부 오버레이 추가 시 레이어 우선순위

현재 이벤트 토큰 레이어와 A면 리사이즈 핸들의 충돌을 처리했다. 이후 더 높은 `z-index`를 가진 전술상황판용 오버레이가 추가되면 그리기 입력을 가로챌 수 있으므로 신규 오버레이에서 `drawing` 모드를 함께 고려해야 한다.

### 새로고침 시 데이터 유실

그림 데이터를 세션 저장소에 기록하지 않으므로 예기치 않은 새로고침이나 브라우저 종료 시 그림이 사라진다. 복원이 필요하면 런타임 세션 저장 형식에 `DrawingStroke[]`를 추가해야 한다.

## 8. 전체 린트 현황

저장소 전체 `npm run lint`는 기존 코드에 누적된 React Hooks 및 Fast Refresh 규칙 오류 때문에 실패한다. 확인 당시 전체 결과는 오류 55건, 경고 10건이다. 이번 기능과 직접 관련 없는 기존 오류이며 프로덕션 빌드에는 영향을 주지 않았다.

신규 Context는 프로젝트의 기존 Context 구성 방식과 동일하게 Provider와 hook을 한 파일에서 내보내므로 해당 hook 내보내기에만 Fast Refresh 규칙 예외를 명시했다. 기존 `ActionModeContext.tsx`의 동일 규칙 오류는 이번 작업 범위에서 변경하지 않았다.
